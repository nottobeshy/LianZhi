# 炼知 · LianZhi

**思考在前，AI 在后。**

**从 AI 帮写，到 AI 陪炼。**

> 你是否遇到过这样的矛盾：明明已经看懂了一个知识点，但当你试着把它讲给别人听时，却发现自己并没有想象中理解得那么清楚？

**炼知（LianZhi）** 是一款面向大学生、知识学习者和个人内容创作者的 AI 辅助学习与表达工具。

它尝试改变我们与生成式 AI 的交互顺序：**让用户先独立思考和表达，再让 AI 通过针对性追问与文案复盘提供帮助。**

我们希望 AI 不只是更快地生成答案，也能帮助用户发现理解盲区、打磨逻辑，逐步形成属于自己的知识表达。

- 本地视频语音转写不需要云端 AI Key。

## 为什么开发炼知？

如今，AI 可以在很短的时间内生成解释、总结和讲稿。

但**得到一份完整的答案，并不等于我们已经具备独立解释它的能力。**

对希望通过知识分享、视频讲解来促进学习的人来说，常常会遇到三个问题。

**01 · 看懂了，却不一定讲得清楚**

阅读材料时觉得自己已经理解，但真正组织语言时，可能发现关键前提、概念联系和推导过程仍然模糊。

**02 · AI 能帮忙生成，却容易跳过自己的思考**

直接获取成品文案固然方便，但如果缺少独立解释与主动修正的环节，用户就很难判断自己究竟掌握了多少。

**03 · 视频录完了，却不知道从哪里改进**

从一段知识讲解视频中发现概念问题、整理口播文案、检查逻辑，再对照修改结果，往往需要耗费不少时间。

炼知将这些过程组织成一条持续改进的路径：

**自主学习 → 独立解释 → AI 追问 → 修正理解 → 视频表达 → 文案复盘 → 作品积累**

知识挑战与视频复盘目前是两个独立入口，用户可以根据实际需要分别使用。

## 核心功能

### 01 · 启发式知识挑战

**先给出自己的解释，再接受 AI 的追问。**

从内置知识词库中选择或随机抽取一个知识点，在限定时间内自主学习，并尝试用自己的语言进行说明。

随后，AI 根据用户实际输入的解释提出针对性问题，帮助检查概念、前提与理解边界。

主要能力：

- 多学科知识词库、导入与随机抽题
- 学习倒计时
- 用户独立解释
- AI 针对性追问
- 回答与修改记录
- 本地知识档案

这不是让 AI 先写出标准答案，而是让用户成为知识表达的主体。

### 02 · 视频口播转写与 AI 复盘

**把自己的讲解转化为可以检查、修改的文案。**

用户可以上传自己录制的知识讲解视频，由本地语音识别模型生成分段转写文本。

人工校对确认后，可以主动授权云端 AI 从知识准确性、逻辑结构和语言表达等方面提出修改建议。系统保留原始版本与 AI 建议修改版，用户也可以继续编辑自己的最终文案。

主要能力：

- 本地 MP4 视频导入
- 本地 ASR 中文语音转写
- 带时间戳的分段文字
- 人工校对与确认
- AI 知识、逻辑及表达优化建议
- 原稿、AI 建议稿与用户编辑稿对照
- 修改版本保存与历史查看

当前单个视频限制为 **180 秒以内、100 MiB 以内**；文件还需满足可解码、含有效音轨等要求。

**本模块分析的是口播转写文本，不是视频画面本身。** 当前版本不提供人物表情、动作或镜头语言分析。

### 03 · 思维演进档案

**重要的不只是最终答案，还有理解发生变化的过程。**

炼知通过 SQLite 在本机保存知识挑战、回答、修正、视频转写和复盘记录。用户可以回顾最初的解释、AI 的追问、自己的回答与修改，以及口播文案在不同版本之间的变化。

知识作品不只是一次性的生成结果，也可以成为下一次思考的起点。

## 炼知有什么不同？

炼知并不试图取代通用 AI，而是提供一种更强调用户主动参与的学习工作流。

| 对比维度 | 常见的 AI 内容生成方式 | 炼知的默认设计 |
| --- | --- | --- |
| 交互起点 | 用户提出需求 | 用户先尝试独立解释 |
| AI 的角色 | 提供答案与成品 | 根据表达提出追问和建议 |
| 用户参与 | 主要审阅生成结果 | 主动回答、修正、重新表达 |
| 视频处理 | 生成或润色文案 | 从真实口播转写出发进行复盘 |
| 内容记录 | 关注最终产出 | 同时保存原稿与修改过程 |

**炼知的设计重点不是让 AI 回答更多问题，而是重新组织用户与 AI 之间的思考顺序。**

## 技术架构

炼知采用本地优先、云端 AI 按需介入的架构。

| 模块 | 技术 |
| --- | --- |
| 前端 | HTML / CSS / JavaScript |
| 后端 | Python / FastAPI |
| 数据存储 | SQLite |
| 本地语音识别 | faster-whisper / CTranslate2 |
| 云端 AI | 可配置的大模型 API（当前实现以 DeepSeek 适配为主） |
| API Key 管理 | Windows 系统凭据存储 |
| 桌面窗口 | pywebview |
| Windows 封装 | PyInstaller |

桌面版通过内置本地 FastAPI 服务运行现有前端，无需另外部署数据库服务。当前面向 Windows 单机用户，并非多人在线协作平台。

详细架构：[ARCHITECTURE.md](docs/ARCHITECTURE.md)

## 从源码运行

建议环境：Windows 11 x64、Python 3.12；Node.js 仅在执行现有前端测试时需要。

### 1. 获取源码

```powershell
git clone https://github.com/nottobeshy/LianZhi.git
cd LianZhi
```

### 2. 创建虚拟环境

```powershell
python -m venv .venv
```

### 3. 安装基础依赖

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 4. 启动应用

```powershell
.\.venv\Scripts\python.exe -m backend
```

浏览器访问：`http://127.0.0.1:8000`  
接口文档：`http://127.0.0.1:8000/docs`

### 5. 启用源码模式的视频转写

源码运行模式需要额外安装语音识别依赖并准备模型：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-asr.txt
.\.venv\Scripts\python.exe scripts/download_asr_model.py
```

完成后启动或重启后端。

**桌面版具有模型自动安装流程；单独运行源码后端不会默认自动下载模型。**

完整说明：[源码复现指南](docs/REPRODUCE.md) · [本地 ASR 说明](docs/ASR.md) · [Windows 构建指南](docs/releases/BUILD.md)

## AI 模型与隐私

炼知采用本地处理与明确授权相结合的方式。

**本地处理**

- 视频文件保存在用户本机。
- 语音识别在本地执行。
- 学习与作品记录保存在本地 SQLite。
- 原始视频和音频不作为云端 AI 复盘的请求内容。

**云端 AI**

当用户主动使用 AI 追问或文案复盘时，相关知识解释或**人工确认后的转写文本**会在用户明确同意后发送给所配置的模型服务。

**API Key**

用户自行输入 API Key，并可选择使用 Windows 系统凭据保存。源码仓库与发行包不包含开发者的私人密钥。

设置中可配置**本地 AI 请求次数限制**。它只用于控制炼知本地调用行为，不代表云端服务商账户的剩余额度。

AI 输出可能存在概念判断错误、遗漏或不恰当改写，建议结合原始表达进行人工核查。

详细说明：[API Key 与安全配置](docs/SECURITY.md)

## 测试与已知限制

项目包含针对 FastAPI、SQLite、知识挑战、视频工作流、桌面生命周期和数据保存的测试。

Windows 候选包已在开发者的 Windows 11 环境中进行桌面启动、本地 ASR、明确标记的 Stub 业务流程、数据持久化和窗口重启验证。**Stub 测试不等于真实云端模型已在发行包中完成端到端验收。** 真实 DeepSeek 调用在此前源码联调阶段有过成功记录，详见历史测试文档。

仍需注意：

- 不代表已通过所有 Windows 设备或全新系统环境的兼容性测试。
- 中文 ASR 的识别结果受口音、噪声和专业词汇影响，建议人工校对。
- 首次安装语音模型需要能够访问下载服务；完成安装后，本地转写可离线运行。
- 云端 AI 功能仍需要网络、有效 API Key 及服务商相应额度。
- 当前版本不提供自动更新、正式 Windows 安装向导或代码签名。
- 模型建议不等于经过外部权威资料核实的知识结论。

完整测试证据与待验证项目：[Windows 测试报告](docs/releases/TEST_REPORT.md)

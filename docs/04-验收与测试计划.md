## 1. 验收范围与判定

- **MVP 必验：22 项 P0 需求。** 每项下列标准及适用的专项用例必须通过；因依赖未准备而无法执行记为“阻塞”，不能记“通过”。
- **后续候选：4 项 P1、3 项 P2。** 本期不实现，不进入 MVP 通过率分母；只有明确批准纳入范围后，才启用对应标准及新增测试。
- 单用户、本机、普通话是建议测试环境；公共部署、多用户、其他语言不在本轮能力声明中。
- 不以 API 返回 200、JSON 可解析、生成了视频、用户满意，单独认定知识正确、理解提升或业务通过。
- 安全底线、数据完整性、双模式闭环、证据可定位不设“演示通过即可”的豁免。

测试记录状态统一为：`未执行 / 通过 / 失败 / 阻塞 / 不适用`。任何“通过”必须有实测日期、设备和版本、实际结果及证据；P1/P2 本期标“不适用”，不得声称它们已经通过。

## 2. 测试准备与样本

| 样本编号 | 准备内容 | 用途与约束 |
| --- | --- | --- |
| FX-01 | 经人工审过的概率统计与 AI 基础知识卡、定位到页码/段落的来源片段；包含“相关不等于因果”等边界例子 | 由人确认来源支持关系，不能由同一个生成模型自评正确；引用时间与来源版本须固定 |
| FX-02 | 对同一知识点的正确解释、典型误解、部分正确解释、只有一句话的解释、纯空白解释 | 验证反馈及空输入；不把简短自动判为不懂 |
| FX-03 | 30–90 秒自录普通话视频、经人校对的逐段参考转写稿，覆盖数字、专有词及一处知识错误 | 有素材授权；记录原片时间轴与错误位置；这不是训练集或真实用户效果数据 |

| FX-05 | 无音轨视频、全静音视频、明显噪声视频、无可辨识语音视频 | 各自可解释失败/提示，不得凭空生成转写或分析 |
| FX-06 | 0 字节文件；文本改名为 .mp4；损坏媒体；超过 100 MiB 文件；时长为 300 秒与超过 300 秒的视频 | 文件大小按 104857600 字节上限，时长以探测值为准；使用受控测试文件，不上传真实敏感媒体 |
| FX-07 | AI 固定返回样本：合法结果、缺字段、非法枚举、代码围栏、多余指令、超长结果、伪来源、越界时间、不存在的段 ID | 用可重复的模拟结果验证防护；模拟结果不可作为真实 AI 效果成绩 |
| FX-08 | 网络断开、API 鉴权失败/限流/超时、依赖缺失、模型缺失、磁盘空间不足、只读目标目录 | 通过可控故障注入验证失败状态与回退，不改动用户已有文件 |
| FX-09 | 空数据库、只有挑战的作品、只有视频的作品、同知识点双记录、不同知识点记录、引用旧转写的报告 | 覆盖档案独立运行、关联约束、过期报告和删除 |
| FX-10 | 含“忽略所有规则”、假系统提示、可疑 HTML、特殊字符路径和类似密钥字串的文本 | 验证不执行用户内容、不读取任意路径、不把敏感输入写入普通日志 |

**执行条件：** 获批 PRD 版本、固定依赖清单、记录模型标识与参数、可用测试 API 预算、审核来源包、授权演示媒体。首次测试前记录 Windows 版本、CPU、内存、可用磁盘、是否有 GPU、ASR 模型及推理设置。真实 API 的测试次数受批准预算限制；确定性故障测试优先使用模拟。

## 5. 测试分层与执行次序

1. **本地确定性检查：** 协议、版本、幂等、匹配、引用、时间边界、跨知识点关联、文件目录边界。以固定样本验证，不依赖真实模型的随机回答。
2. **集成检查：** SQLite 保存/恢复/删除；FFmpeg 实际探测与提音；本地 ASR；模拟 API 的失败、修复和超时。重点检查组件之间的数据是否一致。
3. **真实链路检查：** 先各完成一次最短挑战与短视频复盘，再覆盖未决知识、人工核对、同知识点关联、报告过期。实测模型只运行必要案例并记录费用。
4. **知识内容人工检查：** 对首批全部知识卡及至少 6 条代表性反馈逐条比对来源；正确、错误、条件缺失/证据不足三类均需覆盖。人工复核者可以是项目成员，但要记录身份/日期，不能把模型自评当人工审核。
5. **干净环境与演示彩排：** 按 README 安装；使用提交候选版本执行三分钟演示。网络失效时可展示明确标注的历史结果，同时如实说明实时链路状态。

避免为颜色、文案、单纯布局编写重复实现逻辑的自动化测试；这类低风险可逆改动做人工检查。资源、安全、数据版本和外发边界优先自动化或可重复验证。

## 6. 性能与质量记录方法

| 指标 | 记录方式 | 判定边界 |
| --- | --- | --- |
| 本地交互与保存 | 同设备、相同数据量下测 5 次，记录中位数及最慢值 | 小型本地记录保存目标 ≤1 秒（不含媒体转写）；属于待 D0 实测校准的体验目标，不能先写“已达标” |
| 提音与 ASR | 30/90/300 秒普通话样本各记录媒体长度、阶段耗时、峰值内存、模型设置；至少一次冷启动 | 30–90 秒样片离线转写体验目标 ≤180 秒，设备未测前不承诺；阶段超时硬约束按基线；600 秒超时需证明 ASR 子进程实际终止并释放资源 |
| 转写准确性 | 与人工参考稿比较关键数字、术语、否定词和错误率；可报告 CER，但记录计算规则与样本量 | 不设虚构准确率；任何关键错词需用户能修改；无语言证据时禁止幻觉转写进入报告 |
| 证据定位 | 抽查每条报告的段 ID、逐字引文、时间范围及来源片段 | 进入有效报告的引用必须 100% 通过结构及定位校验；这不等同知识事实 100% 正确 |
| 模型质量 | 人工检查输出是否支持所列主张、是否承认不确定；保留失败案例 | 样本为开发验证，不宣称对全体大学生有效；一条越权“已核实/已掌握”均必须修复 |
| 成本 | 记录每逻辑步骤请求次数、重试次数、模型、用量/费用（可得时） | 与批准预算比较；无法获得精确费用标估算；重复点击不能重复扣费 |

## 7. 缺陷等级与放行

| 等级 | 示例 | 放行规则 |
| --- | --- | --- |
| 阻断 | 数据丢失、越界删文件、泄露密钥、未经同意外发、有效报告含伪引用、模型自授“已核实” | 必须修复并复验；不能带问题发布 |

## 1. 审查结论

当前交付是可打开的静态交互 Demo，已经有四个真实可解析词库、抽题和学习计时；AI、媒体处理、转写和报告仍为 Mock。没有 Python/FastAPI/Streamlit 应用、SQLite 持久化或真实 API/ASR 链路。现有 Node 脚本均退出 0，但部分检查只打印结果且词库测试选错对象，不能据此宣布核心验收通过。隔离检查复现缓存丢失、编辑内容丢失和转写确认失效问题。建议先批准修复这些阻断问题并进行 D0，依据实测结果再批准真实应用集成。

## 6. 架构取舍与 FastAPI + SQLite 风险

**建议采用现有 HTML/CSS/JS + 轻量同源 FastAPI + SQLite，等待批准。** 已有词库、抽题、计时和样式可以保留；Streamlit 方案需要重写视图与事件，旧文档中的 rerun/Session State/.streamlit/upload 设置不能直接沿用。当前静态前端也不能简单只替换 MOCK 就完成集成。

| 项目 | 保留前端 + FastAPI（提案） | 按原 Streamlit 方案重建（旧提案） |
| --- | --- | --- |
| 复用/成本 | 复用布局和大部分交互；需重写异步边界、错误/加载/版本处理 | Python 页面组织较集中，但当前 8 个 JS 的视图、计时和动画多数需重新实现 |
| LLM/ASR | 普通服务层调用；明确任务状态与进度查询，Python 密钥只在服务端 | 同样需真实服务层；页面重跑和后台任务约束按旧文档重新验证 |
| 测试 | 保留 Node 核心检查，加 HTTP/SQLite/媒体集成测试 | 业务单测可复用；现有前端事件层测试/布局不能直接复用 |
| 部署 | 目标为一个本机 Python 进程同时提供静态资源和 API，一个启动入口；待实测 | 依旧需要 Python、FFmpeg、模型和密钥，不能消除媒体部署难点 |
| 交付风险 | 接口与状态改造真实存在，但避免整套页面重写 | 熟悉 Streamlit 才可能快；现有 UI/交互重做增加剩余工期风险 |

关键集成风险及必须验证的边界：

- **异步生命周期**：当前 Store 同步、render 全量重建。每个提交需 request_id、对象身份、输入版本及结果有效性检查；重复按钮/返回晚到不能创建重复档案或覆盖新输入。真实 API 返回 Promise 后调用点全部要逐步改，不能整体替换文件就算完成。
- **同源与文件访问**：建议后端直接提供静态资源，浏览器通过本机 HTTP 访问；不使用 file:// 跨源调用 API。只监听 loopback，限制 Origin/主机和写操作来源，静态/媒体路由不得暴露任意磁盘路径；不开放宽泛 CORS 代替本机安全设计。具体防护需实现后测试。
- **重任务与 SQLite**：避免在异步请求循环直接跑阻塞 ASR；采用受监督子进程并限制同一数据目录一个重任务。短事务、每执行上下文独立连接、参数化 SQL/外键/锁等待；不在等待 LLM/ASR 时持有写事务。实际工作线程及连接组合必须锁版实测。
- **词库迁移**：服务端不能直接读取浏览器 localStorage；file 与 HTTP、不同 host/port 的存储也不共享。需明确可导出/导入的迁移路径，备份原值并保留旧 ID，成功校验前不删除旧缓存；当前没有迁移工具。
- **身份与版本**：数据库稳定 knowledge_item UUID 和快照独立于可改标题/词条位置；确认稿、结果、保存状态不能再靠单个整数/布尔表示。先修 B02/B03，服务端仍须再次保证不可变版本/过期检查。
- **错误与真实性**：缺 Key/401/429/断网/非法 JSON/伪引用均失败且保留输入；示例从明确来源案例读取，不能回退到 MOCK 并伪装实时成功。接口 schema 和引用校验要覆盖 docs/03，API Key 不进入前端。

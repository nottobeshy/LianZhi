# 二、正式确定三层架构

本轮明确采用以下技术路线：

**表现层：HTML + CSS + 原生 JavaScript**

**业务层：Python FastAPI**

**数据层：SQLite**

辅助能力：

- 云端大模型 API：负责 AI 追问、反馈、讲稿整理和视频文本复盘。
- 本地 ASR：负责中文知识讲解视频的语音转写。
- 未来可选 pywebview：负责桌面窗口封装。

## 2.1 架构设计原则

坚持以下原则：

1. 保留现有前端，不使用 React、Vue 或 Streamlit 重建页面。
2. 前端通过 HTTP API 与 FastAPI 通信。
3. FastAPI 负责业务逻辑、数据校验、权限判断与模型服务调度。
4. SQLite 负责用户学习和作品记录的持久化。
5. 模型调用逻辑与业务逻辑分离。
6. ASR 引擎通过独立服务接口接入，便于未来替换。
7. 文件存储与数据库路径可配置。
8. 本地服务默认只监听 127.0.0.1。
9. 不引入当前 MVP 不需要的复杂基础设施。
10. 保持代码可维护、可测试、可复现。

不需要：

- React 前端重写
- PostgreSQL
- Redis
- Celery
- Docker 强依赖
- 用户注册和登录系统
- 微服务拆分
- Kubernetes
- 复杂的 SaaS 权限系统

除非实际需求确实需要，否则不要新增这些组件。

## 2.2 一个统一的本地应用

目标是由 FastAPI 同时托管：

- 现有前端静态页面
- JavaScript、CSS 和资源文件
- 后端 /api/ 接口

使用户启动 Python 服务后，通过一个地址即可访问完整应用：

http://127.0.0.1:8000

目标是形成统一的本地 Web 应用，而不是让用户分别启动多个前端和后端服务器。

不要假定上述地址已可运行；必须通过实际测试确认。

# 五、第一阶段：阻塞性 Bug 检查与修复

在架构集成前，对以下风险进行增量检查。

## 5.1 抽题动画生命周期

检查：

- 页面切换时是否正确取消抽题。
- 取消后是否仍可能触发完成回调。
- 跳过抽题是否会重复锁定。
- 连续点击是否会创建多份并行动画。
- 已经修复的问题是否存在回归。

## 5.2 数据身份标识

确保：

- 知识点使用稳定 ID。
- 持久化记录不依赖知识点显示名称。
- 不同词库同名知识点不会误关联。
- 内置词库和用户导入词库具有清晰身份。

## 5.3 输入与存储

检查：

- 用户输入长度限制是否真正执行。
- 空输入和非法输入是否被阻止。
- localStorage 失败是否有反馈。
- 旧本地数据是否能够兼容。
- 各类异步请求失败后是否保留用户输入。

## 5.4 视频复盘版本状态

检查现有前端是否存在：

用户修改转写文本后，旧 AI 复盘仍显示为最新结果的问题。

后续实现必须保证：

**复盘报告与特定转写版本绑定。**

用户修改并重新确认转写内容后，旧报告必须明确标记为过期，不能当作针对最新文本的分析。

## 5.5 修复原则

先复现，再修复，再测试。

不要重复修复已经解决的问题。

只处理会影响核心功能、数据正确性、后端接入或稳定性的 Bug。

非阻塞性 UI 美化不在本轮范围内。

# 七、第三阶段：第一个真实 AI 业务闭环

这是本轮最重要的交付目标。

必须打通以下完整流程：

**知识词库抽题 → 用户独立解释 → FastAPI 接收文本 → 真实大模型提出针对性追问 → 前端展示追问 → 用户回答和修正 → SQLite 保存记录 → 重启后重新读取。**

## 7.1 用户交互

尽量复用现有前端。

不要重新设计知识挑战页面。

前端只负责：

- 收集用户输入
- 调用 API
- 展示加载状态
- 展示真实 AI 结果
- 展示错误信息
- 读取历史记录

## 7.2 大模型适配层

将模型调用封装为独立服务。

至少考虑：

- 可配置 API endpoint
- 可配置模型名称
- API Key
- 请求超时
- 失败处理
- 结构化响应
- 模型输出校验
- 服务不可用时的明确提示

具体 API 服务商、模型及真实调用测试，在需要密钥或产生费用时，应先向我确认。

如果真实模型条件尚不具备，可以先使用明确标记的 Stub 完成 HTTP + SQLite 的测试，但不能宣称真实 AI 已接入完成。

## 7.3 追问质量

AI 追问不应该只是：

“请你进一步解释这个知识点。”

而应当结合：

- 当前知识点
- 用户实际解释
- 用户可能存在的误区
- 已经提出的问题
- 用户上一轮回答

生成具有针对性的追问。

如果用户的解释基本正确，也应允许 AI 提出边界条件、反例或进一步理解问题，而不是为了制造“漏洞”强行判错。

不要将模型反馈包装为权威、绝对正确的知识能力评分。

## 7.4 安全与隐私

遵循：

**思考在前，AI 在后。**

用户必须先完成独立解释，再进入 AI 追问流程。

云端模型请求需要明确授权。

不得将 API Key：

- 写入前端 JavaScript
- 写入源码
- 提交 Git
- 写入 SQLite
- 写入普通日志

对于通过设置界面输入的 API Key，优先采用后端会话内存保存，不做持久化。

对于开发环境使用的环境变量，也必须确保不提交实际密钥。

明确区分：

- live：真实模型结果
- example：预先保存的示例
- mock：开发或测试模拟数据

三种状态不能混淆。

# 九、后续阶段：视频转写与表达复盘

本轮仅要求保留接口设计空间，不要求一次性完成完整 ASR。

后续开发目标如下。

## 9.1 本地语音识别

用户上传自己的中文知识讲解视频。

本地处理媒体，生成：

- 语音文本
- 分段开始时间
- 分段结束时间
- ASR 引擎及模型信息

需要保证原始音视频不会在未经授权时发送到云端。

## 9.2 ASR 引擎选型

候选：

- faster-whisper
- FunASR / Paraformer-zh

应先对相同中文测试素材进行小规模实测。

评估：

- 中文识别错误率
- 专业词汇表现
- 转写耗时
- CPU/RAM/显存占用
- 时间戳可用性
- Windows 安装难度
- 稳定性
- 许可证
- 评委复现成本

根据测试结果选择正式引擎。

不要仅根据项目知名度或理论性能做决定。

## 9.3 转写文本人工确认

用户必须能够：

- 查看转写结果
- 修改识别错误
- 确认最终文本

未经用户确认，不触发云端 AI 复盘。

## 9.4 复盘版本一致性

AI 复盘报告必须绑定具体转写版本。

当用户修改文本：

- 新建或更新对应文本版本。
- 旧复盘报告标记过期。
- 不允许旧分析冒充新分析。
- 再次复盘生成新版本。

## 9.5 分析边界

如果模型实际只接收转写文本，报告只能分析文本能够支持的内容，例如：

- 概念表述
- 逻辑连贯性
- 语言冗余
- 讲解结构

不能声称已经分析：

- 表情
- 肢体动作
- 镜头语言
- 视觉表现

除非未来确实实现对应多模态能力。

不要为了将来可能存在的需求过度设计。

# 十四、开发与汇报方式

请按以下顺序执行：

**第一步：检查工程**

阅读源码与文档，确认实际状态，列出阻塞性问题。

**第二步：确认实现方案**

给出简短的目录与 API 设计，明确本轮所需依赖。

对于已授权的三层架构，无需反复请求架构批准；对于收费 API、下载大型模型、破坏性数据迁移或超出范围的决策，需要先征求我的同意。

**第三步：实现最小闭环**

分小步修改，每一步都运行对应测试。

**第四步：真实联调**

用现有前端实际操作，不要只通过单元测试宣称前后端整合成功。

**第五步：工程复现检查**

验证启动路径、依赖、数据库和无密钥体验。

**第六步：文档同步**

更新 HANDOFF.md、README.md、架构和复现文档。

**第七步：提交阶段成果**

提供：

1. 实际完成内容。
2. 修改文件列表。
3. API 接口说明。
4. 数据库设计说明。
5. 实际测试结果。
6. 可复制的启动命令。
7. 尚未完成内容。
8. 下阶段视频复盘开发建议。

本轮完成后暂停，等待我验收，再开始下一阶段开发。

# 十五、最终验收标准

本轮验收的核心不是“生成了多少代码”，而是以下场景能否真实完成：

**场景一：**

我打开「炼知」，前端能够正常加载，原有词库与抽题功能没有损坏。

**场景二：**

我抽取一个知识点，输入新的解释，点击 AI 追问。

在配置真实 API 并授权后，系统确实调用云端模型并返回针对当前输入的问题。

**场景三：**

我完成一次解释、追问和修正，系统把相关内容写入 SQLite。

**场景四：**

我关闭软件服务并重新启动，仍然可以读取刚才的挑战记录。

**场景五：**

我将代码仓库复制到另一个干净目录，根据 README 完成启动和基础测试，不依赖原开发目录中的隐藏文件。

**场景六：**

没有 API Key 时，程序不会崩溃，也不会虚构 AI 结果，而是明确提示模型未配置，并提供基础功能与预存示例体验。

以上实际完成并测试通过，才能认为本轮 MVP 核心工程闭环完成。

**再次强调：先真实可用，再扩展功能；先确保工程可复现，再考虑桌面封装；每次代码修改都必须同步 HANDOFF.md 和相关工程文档。**
